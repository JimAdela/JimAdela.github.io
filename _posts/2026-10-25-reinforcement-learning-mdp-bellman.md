## 开篇：这篇要解决什么

监督学习有一个舒服的前提：每一道题都有标准答案。图片是猫，标签就写猫；翻译错了，参考答案就在旁边。损失函数拿预测和答案一比，梯度就出来了。

强化学习没有这个前提。你只知道"刚才那一手，最后赢了"或者"三天后这个推荐策略把留存拉高了 2%"，中间几十上百个决策里，究竟哪一步做对了、哪一步做错了，没人告诉你。**奖励是延迟的、稀疏的、而且是关于一整条轨迹的**。

大多数人在这一步卡住，不是因为不会推导，而是因为符号太密：$S$、$A$、$P$、$R$、$\gamma$、$V^\pi$、$Q^\pi$、$V^*$、$Q^*$ 一次性砸过来，每个都认识，合起来就不知道在说什么。这篇的目标很具体：**读完你能自己手算一个小规模 MDP 的值函数，能手写一个三十行的值迭代，并且知道它在什么情况下会骗你。**

## 第二十三章：强化学习：马尔可夫决策与贝尔曼方程

### 1. 直觉：一个只会记账的赌徒

先把比喻立起来，公式后面再上。

想象你站在一个岔路迷宫里，每走一步要花 1 块钱，某些格子上有钱可以捡。你现在站的位置、身上还剩的钱、以及你对这个迷宫的记忆，共同构成了你的**状态**。你可以往四个方向走，这就是**动作**。走到某个格子捡到钱，这就是**奖励**。

现在问一个看起来很简单的问题：**站在这个路口，我接下来总共还能净赚多少？**

注意这个问题问的不是"这个路口好不好"，而是"**按照我现在的走法**，从这个路口出发，未来所有收支折算到今天，是多少"。这个数就是**值函数** $V^\pi(s)$。上标 $\pi$ 是策略，也就是"我在每个路口习惯往哪走"的那套规则。

这里有个必须说清楚的区分，很多人第一次学就混淆：

- **奖励**是即时的、一步的。捡到 5 块就是 5 块。
- **值**是累积的、期望的、打了折的。它是对**策略**的评价，不是对**环境**的描述。

同一张迷宫图，换一套走法，每个路口的 $V$ 就全变了。所以 $V$ 永远带着 $\pi$ 的帽子。这是强化学习和"图论最短路"最大的区别——最短路的最佳值只由地图决定，而 RL 的值由地图**和**你的行为共同决定。

那贝尔曼做了什么？他指出了一个几乎像废话、但威力巨大的观察：

> 从现在开始能赚到的总钱数 = **下一步立刻赚到的钱** + **从下一步的位置继续赚到的总钱数（打折后）**

未来的账，可以拆成"一步"加"剩余的账"。这个递归一旦成立，一个关于无穷未来的问题，就退化成了一个关于相邻两格的方程。**贝尔曼方程不是新定理，它是"总账 = 第一笔 + 余账"这句话的数学写法。**

### 2. 数学形式

#### 2.1 马尔可夫决策过程

一个 MDP 是五元组 $(\mathcal{S}, \mathcal{A}, P, R, \gamma)$：

- $\mathcal{S}$：状态集合
- $\mathcal{A}$：动作集合
- $P(s', r \mid s, a)$：在状态 $s$ 执行动作 $a$ 后，转移到 $s'$ 并获得奖励 $r$ 的联合概率
- $R$：奖励函数（通常写作期望形式 $R(s,a) = \mathbb{E}[r \mid s,a]$）
- $\gamma \in [0,1)$：折扣因子

策略 $\pi(a \mid s)$ 给出在状态 $s$ 选动作 $a$ 的概率。从时刻 $t$ 出发的**回报**定义为折扣累积奖励：

$$
G_t = \sum_{k=0}^{\infty} \gamma^{k} R_{t+k+1}
$$

值函数就是回报的条件期望：

$$
V^\pi(s) = \mathbb{E}_\pi\!\left[G_t \mid S_t = s\right], \qquad
Q^\pi(s,a) = \mathbb{E}_\pi\!\left[G_t \mid S_t = s, A_t = a\right]
$$

$V$ 回答"站在这个状态值多少"，$Q$ 回答"站在这个状态、且**先做这个动作**值多少"。$Q$ 比 $V$ 多一层信息，因为动作还没被策略平均掉。

#### 2.2 贝尔曼期望方程

把 $G_t$ 拆成第一项加余项，两边取期望，就得到：

$$
V^\pi(s) = \sum_{a} \pi(a\mid s) \sum_{s', r} P(s', r \mid s, a)\left[\, r + \gamma\, V^\pi(s') \,\right]
$$

$$
Q^\pi(s,a) = \sum_{s', r} P(s', r \mid s, a)\left[\, r + \gamma \sum_{a'} \pi(a'\mid s')\, Q^\pi(s', a') \,\right]
$$

两式的结构完全一样：**即时奖励 + 折扣 × 后继状态的值**。区别只在于第一层有没有对动作求平均。

写成矩阵就是一行线性方程（把 $P^\pi$ 和 $R^\pi$ 按策略边缘化之后）：

$$
V^\pi = R^\pi + \gamma P^\pi V^\pi
\quad\Longrightarrow\quad
V^\pi = (I - \gamma P^\pi)^{-1} R^\pi
$$

**这就是最关键的一个结论**：给定策略，值函数有闭式解，不需要迭代。$\gamma < 1$ 保证 $I - \gamma P^\pi$ 可逆（因为 $P^\pi$ 是随机矩阵，谱半径不超过 1，$\gamma$ 一乘就严格小于 1）。

#### 2.3 一个能手算的两状态例子

只有两个状态 $A, B$，两个动作"走"和"停"。

- 在 $A$ 只能"走"到 $B$，奖励 0
- 在 $B$ 只能"停"在原地，奖励 1
- $\gamma = 0.9$

策略固定为这条链。于是 $P^\pi = \begin{bmatrix} 0 & 1 \\ 0 & 1\end{bmatrix}$，$R^\pi = \begin{bmatrix} 0 \\ 1 \end{bmatrix}$。

直接代入闭式解：

$$
V = (I - 0.9P)^{-1}R
= \begin{bmatrix} 1 & -0.9 \\ 0 & 0.1 \end{bmatrix}^{-1}
\begin{bmatrix} 0 \\ 1 \end{bmatrix}
= \begin{bmatrix} 1 & 9 \\ 0 & 10 \end{bmatrix}
\begin{bmatrix} 0 \\ 1 \end{bmatrix}
= \begin{bmatrix} 9 \\ 10 \end{bmatrix}
$$

手工验算也对得上：$V(B) = 1 + 0.9\,V(B) \Rightarrow V(B) = 10$，而 $V(A) = 0 + 0.9 \times 10 = 9$。

注意 $10$ 这个数字的来源：$1/(1-0.9)$。**$\gamma$ 的倒数差额就是"有效视界"**——$\gamma = 0.9$ 意味着你大致只看未来 10 步，$\gamma = 0.99$ 就是 100 步。这比任何"折扣是为了数学收敛"的解释都更接近工程直觉。

#### 2.4 值迭代：从闭式解到能跑的代码

闭式解要求你知道 $P$，也就是知道环境模型。真实问题里通常不知道，但即便如此，值迭代仍是理解一切 RL 算法的地基。它反复套用**贝尔曼最优算子**：

$$
V_{k+1}(s) = \max_{a} \sum_{s', r} P(s', r\mid s,a)\left[\, r + \gamma V_k(s') \,\right]
$$

在上面的两状态例子里，如果允许 $A$ 选择留或走，且从 0 开始迭代，可以得到一个干净的闭式解 $V_k(B) = 10(1 - 0.9^k)$：

| 迭代轮次 $k$ | $V_k(A)$ | $V_k(B)$ |
|---|---|---|
| 0 | 0 | 0 |
| 1 | 0 | 1.000 |
| 2 | 0.900 | 1.900 |
| 3 | 1.710 | 2.710 |
| 4 | 2.439 | 3.439 |
| $\to\infty$ | 9 | 10 |

误差按 $0.9^k$ 衰减，第 4 轮还剩 $10 \times 0.9^4 = 6.56$，和第 4 行完全吻合。这不是巧合，而是压缩映射的直接结果（下面 3.3 会展开）。

下面这段代码可以直接照抄运行，四乘四网格、每步 -1、撞墙原地不动：

```python
import numpy as np

N, GAMMA, THETA = 4, 0.9, 1e-6
TERMINAL = {0, N * N - 1}          # 左上角与右下角是终点
MOVES = [(-1, 0), (1, 0), (0, -1), (0, 1)]   # 上下左右
V = np.zeros(N * N)

def step(s, a):
    """给定状态与动作，返回 (下一状态, 即时奖励)。"""
    r, c = divmod(s, N)
    dr, dc = MOVES[a]
    nr = min(max(r + dr, 0), N - 1)
    nc = min(max(c + dc, 0), N - 1)
    return nr * N + nc, -1.0       # 每走一步 -1，鼓励最短路径

for k in range(1, 5001):
    delta, new_V = 0.0, V.copy()
    for s in range(N * N):
        if s in TERMINAL:
            continue
        q = []
        for a in range(4):
            s2, r = step(s, a)
            q.append(r + GAMMA * V[s2])   # 即时奖励 + 折扣 × 后继状态的值
        new_V[s] = max(q)          # 贝尔曼最优算子
        delta = max(delta, abs(new_V[s] - V[s]))
    V = new_V
    if delta < THETA:
        print(f"第 {k} 轮收敛，最大变化 {delta:.2e}")
        break

print(V.reshape(N, N).round(2))
```

跑出来你会得到一张"离终点越远、值越低"的梯度表：第 $d$ 步到达终点的格子，值恰好是 $-(1-\gamma^{d})/(1-\gamma)$，也就是距离的一个严格单调函数。**值迭代算出来的从来不只是"好坏"，它还把几何结构一起算出来了。**

### 3. 边界与常见误解

#### 3.1 马尔可夫性不是"环境没有记忆"

这是最容易被误读的一条。马尔可夫性的意思是：**当前状态已经编码了做决策所需的全部信息**，与历史无关。

它不要求环境本身无记忆，它要求**你的状态表示**足够充分。你只给 agent 当前帧画面而不给上一帧，它就无法判断球往哪个方向飞——环境仍是马尔可夫的，但你的表示不是，问题已经退化成部分可观测（POMDP）。工程上 90% 的"RL 训练不收敛"，根因是状态设计漏了关键变量，而不是算法选错。

#### 3.2 折扣因子不是"耐心旋钮"

$\gamma$ 同时控制三件事，调它的时候要一起想：

1. **视界长度**：约 $1/(1-\gamma)$ 步；
2. **值的量级**：上界 $\lVert V \rVert_\infty \le R_{\max}/(1-\gamma)$，$\gamma = 0.999$ 时上界放大一千倍，回归目标会非常难拟合；
3. **收敛速度**：迭代误差按 $\gamma^k$ 衰减，见下一条。

所以"把 $\gamma$ 调大一点让它看得更远"不是免费的，代价是训练更慢、方差更大、数值更难稳住。

#### 3.3 贝尔曼方程本身不是算法

它只是一个**一致性条件**——"如果 $V$ 是对的，它必须满足这个式子"。真正能算出东西的是 $V \leftarrow \mathcal{T}V$ 这个迭代，而它收敛的原因是一个独立的事实：当 $\gamma < 1$ 时，贝尔曼算子在无穷范数下是 $\gamma$-压缩的，

$$
\lVert \mathcal{T}V_1 - \mathcal{T}V_2 \rVert_\infty \le \gamma \lVert V_1 - V_2 \rVert_\infty
$$

由巴拿赫不动点定理，它存在唯一不动点，且误差每轮至少乘 $\gamma$。这会带来一个特别实用的估算：达到精度 $\varepsilon$ 所需轮数约

$$
k \approx \frac{\ln \varepsilon}{\ln \gamma}
$$

$\gamma = 0.99$、$\varepsilon = 10^{-3}$ 时需要约 688 轮；$\gamma = 0.999$ 时需要约 6900 轮。**这就是为什么"把折扣因子调到 0.999"经常让实验看起来卡住了**——它没卡，它只是在慢慢爬。

反过来，如果没有终止状态、$\gamma = 1$，压缩性消失，值可能是无穷，迭代不保证收敛。这不是代码 bug，是设定越界。

#### 3.4 那个 $\max$ 的位置不能挪

贝尔曼最优方程是

$$
V^*(s) = \max_{a} \sum_{s'} P(s'\mid s,a)\left[\, r + \gamma V^*(s') \,\right]
$$

$\max$ 在**期望外面**：先看每个动作在所有可能后果下的平均表现，再挑最好的那个。如果写成 $\sum_{s'} P \cdot \max_a [\cdots]$，等价于"每个分支都假设自己运气最好"，得到的是一个系统性偏乐观的值。这个错误在自定义 loss 时非常常见，症状是训练指标虚高、上线就崩。

#### 3.5 奖励塑形会改变最优策略

为了让 agent 学得快一点，很多人会加引导奖励，比如"离目标近一点给 +0.1"。问题是：**你改变了 MDP，最优策略就跟着变了。** 常见的翻车是 agent 学会绕着目标打转刷那 0.1，而不是真的抵达终点。

有一个明确的例外：如果塑形项是某个势函数 $\Phi$ 的差分形式

$$
r' = r + \gamma \Phi(s') - \Phi(s)
$$

那么最优策略不变（这是势函数塑形的经典结论）。除此之外的经验性加奖励，都应该被当成"修改了任务"来对待，需要重新验证，而不是当成加速技巧。

#### 3.6 表格法在真实规模下会直接死掉

上面的代码用数组存 $V$，每个状态一个格子。一旦状态是"用户 30 天行为序列 + 商品 embedding"，状态数是指数级的，表格立刻不可行。出路只有一条：用函数逼近 $V_\theta(s)$ 替代查表。而函数逼近一进来，压缩性、收敛性、采样相关性这些假设全部要重新讨论——这正是下一章要处理的问题。

## 小结

- 值函数是对**策略**的评价而不是对环境的描述，$V$ 永远带 $\pi$ 的帽子；贝尔曼方程只是"总账 = 第一笔 + 余账"的数学写法。
- $\gamma$ 一条参数控制三件事：有效视界 $1/(1-\gamma)$、值的量级 $R_{\max}/(1-\gamma)$、收敛轮数 $\ln\varepsilon/\ln\gamma$——调它必须三个一起算。
- 马尔可夫性约束的是你的**状态表示**够不够充分，不是环境有没有记忆；绝大多数训练不收敛的根因都在这里。
